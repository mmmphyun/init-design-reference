# Contributing Guide

[한국어](CONTRIBUTING.md) | English

Thank you for your interest in `init-design-reference`. This guide helps you contribute while maintaining the core architectural principles of the project.

## 1. Welcomed Contributions

Small, focused contributions are the most welcomed:

- **New AI Anti-Patterns**: If you observe repeated UI clichés generated by modern LLMs (Claude, ChatGPT, Gemini, etc.), propose clear negative constraints in `templates/notes/do-not-copy.md`.
- **Framework & Style Engine Detection**: Add detection logic for new frontend frameworks (Astro, SolidStart, Remix, etc.) or styling engines (Panda CSS, Vanilla Extract, etc.) to the `detect_project_context` function in `scripts/adapter.py`.
- **Domain-Specific Token & Typography Presets**: Propose curated typography stacks or color palettes optimized for specific domains (finance dashboards, developer tooling, tech blogs, etc.).
- **Environment & Bug Fixes**: Report and fix path or execution issues across Windows, macOS, Linux, or within agents like Google Antigravity, Claude Code, and Cursor.

## 2. Core Architectural Principles

Before opening a pull request, ensure compliance with these three design rules:

1. **Decoupled Logic and Templates**:
   - Never hardcode HTML, CSS, or Markdown string literals inside Python scripts.
   - All templates must live as pure files inside the `templates/` directory.
2. **Simplicity and Light Weight (YAGNI)**:
   - This project is a lightweight scaffolding skill invoked by coding agents.
   - Do not introduce heavy build tools, bundlers, runtime network downloads, or unnecessary abstraction layers.
3. **Strict Idempotency**:
   - Never overwrite existing user reference files or custom tokens unless `--force` is explicitly passed.

## 3. Local Verification

Run the unified integrity check script to ensure all tests pass before opening a PR:

```powershell
python scripts/verify_repo.py
```

This script verifies:
1. Python syntax compilation
2. JSON schema validity in `templates/tokens/*.json`
3. Presence of mandatory templates and documentation
4. Decoupled architecture enforcement (no hardcoded template content in scripts)
5. Isolated workspace scaffolding, idempotency (consecutive run), and force-overwrite verification

## 4. Pull Request Guidelines

- Use concise and standard commit messages:
  - Example: `feat: add detection for Astro framework`, `fix: resolve installer path resolution on Linux`
- Include in your pull request description:
  - What changes were made and why
  - Confirmation of passing local verification
